# Agent Note：校验工具截止时间是否处于主机定时器范围内

Status: implemented

[English](2026-08-18-tool-timeout-host-range.md) | 中文

## 问题

`ToolDefinition.timeoutMs` 接受任意正有限值，而已交付的 deadline 原语会拒绝超过主机定时器最大值 `2,147,483,647` 毫秒的数值。因此，工具可以成功注册并对模型可见，却在每次调用时于主体运行前失败。`web_search` 等可配置工具也会在部署选择更大预算时暴露同一种延迟失败。

## 决策

类型化 `defineTool` 辅助函数与原始 `ctx.tools.register()` 边界都依据 `@deepseek-ai/dsh-timeout` 的 `MAX_TIMER_DELAY_MS` 校验 `timeoutMs`。持久 Bash 在 Schemastery 配置和直接 `apply()` 边界应用同一上限。零、负数、非有限值及更大数值都会在注册或命令执行前失败。注册表、持久 shell 与官方 timeout policy 现在接受同一组区间；恰好等于最大值的数值仍然有效。

代码导入共享常量，而不重复写出数值，因此定时器范围发生变化时，工具注册与强制执行不会出现不同上限。本次变更只校验声明；timeout policy 仍负责启动 deadline，工具仍通过 `exec.signal` 协作停止。

## 验证与边界

原始注册、`defineTool` 与持久 Bash 配置测试除覆盖零和非有限值外，还覆盖共享最大值之上的第一个数值。既有正预算与持久命令测试保留普通路径。本修复不会改变默认超时，不会为未声明超时的工具添加统一期限，也不会把协作式取消变成硬终止。

## 考虑过的替代方案

**只在 timeout policy 执行时拒绝。** 这样会保留旧注册表约定，但无效工具仍对模型可见，并把部署错误变成反复出现的模型调用失败。

**只校验 Web 工具。** 这样能关闭已报告的配置路径，却仍允许其他可扩展工具插件发布同样无效的声明。

**钳位到主机最大值。** 静默钳位会改变部署声明的截止时间，并可能掩盖单位错误。因此注册过程会拒绝不支持的数值。

## 影响

无效工具截止时间会在最早的共享声明边界失败，并使用由 timeout 库拥有的单一跨平台上限。`dsh-tools` 增加对无状态 `dsh-timeout` 工具库的依赖，持久 Bash 也在配置边界导入同一常量，使注册与强制执行无法漂移。
