# Agent Note: 工具 schema 聚合预算

Status: implemented

[English](2026-08-17-aggregate-tool-schema-budget.md) | 中文

## 问题

相互独立的工具提供方与 `system-prompt/assemble` 监听器可以持续扩大面向模型的工具 schema 数组，但完整请求没有大小限制。单工具校验无法防止聚合请求头异常增大，进而增加重复输入成本或超过提供方的请求容量。

## 决策

`dsh-system-prompt` 对最终 `PromptAssembly.tools` 数组实施 `maxAggregateToolSchemaBytes` 限制，默认值为 262144 字节。该指标是数组 JSON 序列化结果的 UTF-8 字节长度，并在组装 waterfall 以及最终 complete 段／runtime-context 约束之后计算，此时所有面向模型的工具均已确定。

超限组装会在模型请求前失败。系统不会省略 schema，因为展示少于执行注册表所含工具的能力集合需要显式限制策略，任意省略可能移除任务所需能力。若部署方有意使用更大的 schema 集合，可以提高这个经过校验的正整数限制。共享 agent 主干与 ACP 应用会声明并转发该值，但不重新定义其默认值。

## 曾考虑的替代方案

**分别限制每个工具。** 多个单独合规的 schema 仍可能超过完整请求预算，因此单工具限制无法实施所需的聚合上限。

**在 waterfall 前检查。** 组装监听器可以在检查后添加或替换工具，从而绕过限制。

**静默移除 schema，直至请求符合限制。** 省略策略需要了解任务，并与执行能力保持一致。按字节顺序截断会不可预测地隐藏能力，并把配置错误伪装成模型失败。

**估算 token 而非字节。** Token 数量因提供方和 tokenizer 而异。JSON 字节限制提供确定且与提供方无关的传输保护；token 与上下文窗口核算仍属于独立问题。

## 后果

工具 schema 在多个提供方和组装扩展之间的增长受到限制，包括多字节描述。精确字节边界在各平台上保持确定。超限部署会明确失败，必须限制工具或提高上限；该限制不承诺所有提供方都接受相应大小的请求，也不承诺 schema 能放入模型上下文窗口。

定向测试覆盖低于限制、恰好等于限制、聚合超限、多字节文本、waterfall 后新增工具和无效配置。无密钥 Headless 组合会固定适配器分发前的终端失败行为。
