# Agent Note：整体拒绝过期的设置快照

Status: implemented

English | [English](2026-08-18-ui-settings-stale-snapshot.md)

## 问题

`SettingsScopeController` 会抑制过期读取解码出的值，却仍复制 revision、base 和 user 字段。较旧读取被取代、较新的读取失败时，快照的值可能属于一个 revision，而元数据属于另一个 revision。

## 决策

当读取代数过期时，`accept()` 现在直接返回，不再修改 store。只有同一个命名空间视图会作为一个候选快照发布，因此 `value`、`base`、`user`、`revision` 和状态始终来自同一份视图。README 合约也明确过期读取不会修改快照。

## 验证

定向 UI settings 测试通过，其中包括延迟的旧读取紧接着较新的失败读取。回归测试确认原有值和 revision 仍保持配对。本修复不增加重试行为，也不声称不可用的传输层能在没有后续失效通知或显式 load 时自行恢复。

## 考虑过的替代方案

**只发布元数据而不发布值。** 这正是原有行为，并产生了跨 revision 的混合快照。元数据属于值的 fencing 合约，因此不能单独发布。

**重试每一次失败读取。** 重试会改变传输策略，并可能让已销毁或离线的 scope 无限保持活动。本修复只拒绝过期发布，恢复仍由现有失效通知或显式 load 负责。

## 影响

最新读取失败时，最后一份一致快照保持不变。成功返回的过期响应不再能脱离其值而推进 revision 元数据。在后续读取成功前，服务端可能比客户端更新，但这种状态是明确的，不再表现为本地混合快照。
