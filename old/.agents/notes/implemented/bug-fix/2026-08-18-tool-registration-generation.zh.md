# Agent Note：将已接纳调用固定到一个工具注册代次

Status: implemented

[English](2026-08-18-tool-registration-generation.md) | 中文

## 问题

工具运行时在调用进入策略流水线时和主体最终分发时分别解析实时注册表。因此，入口处未知的工具如果在 `tools/pre-execute` 等待期间被注册，同一次调用就会变为可执行。类似地，已接纳工具可在分发前被卸载、遮蔽或替换，而同一次调用会静默执行新注册。智能体循环可能已经依据旧定义把调用分类为并行，于是独占的替换实现会在自己从未声明的并发许可下运行。

只比较定义对象身份仍不足以闭合缺口：插件可以卸载后重新注册同一个对象，从而产生新的 effect 所有注册代次，但 JavaScript 引用保持不变。

## 决策

每个 `ToolLayer` 在受信任定义外保存一层内部 `ToolRegistration` 记录。每次成功调用 `register()` 都创建不同记录，即使复用同一个定义对象。`createExecution()` 在前置策略之前捕获当时精确可见的记录。只有该记录仍是当前可见且可执行的路由时，主体分发、环绕包装层成功结果规范化和后置策略值替换才会继续。

若路由在主体调用前被删除、限制、遮蔽、替换或重新注册，已接纳调用会以 `UNKNOWN_TOOL` 安全失败。变更后才进入的调用正常解析新注册。保留的 Code Mode 传输在运行时生命周期内使用一条稳定记录。

该边界不会在主体已经调用后撤销它。已启动工作仍遵循协作式取消与静默收敛约定：观测或转发 `exec.signal`，等待自己拥有的工作结束，然后才返回。

## 验证与边界

确定性的 Promise 门闩覆盖：前置策略期间注册此前未知的 raw 工具、用独占定义替换并行定义、用后出现的 scoped 注册遮蔽全局路由，以及卸载后重新注册同一个定义对象。完整 tools、Code Mode、agent-loop 调度、timeout-policy 与持久 Bash 受影响测试集通过。

定义仍是受信任的同进程对象。原地修改仍处于注册状态的同一个定义字段，不会创建新注册代次。即使等价注册立即接替，注册表变更也可能使已经接纳但尚未分发的调用失败；这是有意选择的安全失败结果。

## 考虑过的替代方案

**在每个阶段继续解析实时定义。** 这样 HMR 可以更新已经接纳的调用，但也会允许追溯授权，并可能依据另一个定义的并发分类来分发工具。

**只快照定义对象。** 这能阻止普通替换，却无法识别卸载后重新注册同一个对象，因此不能正确表示 effect 所有权或 HMR 代次。

**注册卸载后仍执行捕获的定义。** 这能保持调用连续，却会在能力所有者声明拆卸后继续调用其代码，也会阻止前置策略期间安装的限制安全拒绝调用。

**在主体分发前立即重新分类。** 当调度器已经让该调用与并行兄弟调用重叠时，无法再安全地把它转为独占；这种方式也仍会让入口处未知的调用获得追溯授权。

## 影响

一次调用现在从查找、并发接纳、策略、分发到输出契约规范化都使用同一个注册身份。HMR 对后续调用仍然实时生效，而已接纳调用无法跨越插件代次。分发前的注册变动表现为 `UNKNOWN_TOOL`，以偶发但可重试的失败换取确定性的能力所有权和安全失败调度。
