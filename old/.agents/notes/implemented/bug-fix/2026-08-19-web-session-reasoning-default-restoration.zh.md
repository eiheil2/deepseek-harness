# Agent Note：Web 会话恢复时保留推理默认值的归属

Status: implemented

[English](2026-08-19-web-session-reasoning-default-restoration.md) | 中文

## 问题

Web 网关恢复日志中最新的 `reasoningEffort` 时，没有读取请求 header 的 `adapterDefaults.reasoningEffort` 标记，而是直接把它作为显式会话选择。适配器实体化的值因此会在恢复后被固定。若适配器随后更改默认值或不再提供该值，下一次请求就可能以 `UNSUPPORTED_REASONING_EFFORT` 拒绝，而不是解析当前默认值。

## 决策

日志中的提供方和模型仍用于恢复会话路由。只有 header 未把推理强度标为适配器实体化时，系统才会恢复日志中的强度。适配器默认值不会进入 `ModelSelection`，因此普通的精确模型解析会选择适配器的当前默认值。用户的显式选择保持不变。

## 验证与边界

回归测试分别以两种归属记录相同的 `max` 强度。修复前，适配器默认值错误地出现在 `session.models.current` 和下一次请求提案中，而显式分支通过。修复后，默认值分支生成不带强度的提案，并解析为适配器当前的 `high` 默认值；显式分支仍为 `max`。

聚焦回归、TypeScript 与 Oxlint 检查均通过。Host API proxy 完整包在 15 秒测试超时下通过全部 382 项测试。在默认 5 秒超时下，并行审计负载期间，一个未修改的大可见集搜索测试两次超过时限；该测试的隔离延长超时运行通过。本次变更不改变当前进程中作出的选择，也不改变 `session.selectModel` 的行为；后者有意持久化其已解析选择。

## 考虑过的替代方案

**恢复日志中的所有值。** 这会保留历史请求的精确值，却丢失 header 已记录的归属，并把过去的默认值转变为未来请求的显式要求。

**丢弃日志中的所有推理强度。** 这能避免陈旧默认值，却也会丢弃同一模型仍然有效的用户显式选择。

## 后果

恢复后的 Web 会话会采用更新后的适配器默认值，不会发生跨模型或跨版本的强度污染。历史请求 header 仍精确记录已发送的内容，而 `ModelSelection` 只包含应控制未来请求的显式选择。
