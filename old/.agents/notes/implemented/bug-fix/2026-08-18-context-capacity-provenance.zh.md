# Agent Note：保留上下文容量来源

Status: implemented

[English](2026-08-18-context-capacity-provenance.md) | 中文

## 问题

模型上下文元数据同时携带容量，以及该容量是否为适配器回退估算值。运行时没有校验来源标记，智能体循环也只按路由和容量数值去重。因此，适配器可以把非布尔标记带到会话边界；或者部署把同一容量从估算值改成精确值时，持久化的 request/context 不会更新，UI 与压缩消费方会继续看到过时来源。

## 决策

`LlmRuntime.resolveModelInfo()` 只接受正的安全整数 `contextWindow`，并要求存在时 `estimated` 必须是布尔值。无效值在适配器所属的查询仍在报告时以 `INVALID_MODEL_CONTEXT` 失败。

智能体循环在追加 `request/context` 前，除了比较 provider、model 与 `contextWindow`，还会比较 `contextEstimated`。容量不变但来源变化时会写入新的持久记录。上下文压力投影把每条容量记录视为完整值：省略估算标记会清除旧标记，而不是让它跨路由继承。

## 验证与边界

LLM service 测试拒绝不安全的上下文整数和非布尔估算标记。Agent-loop request reconstruction 测试覆盖相同路由与容量下从估算到精确的转换。Token-meter 投影测试覆盖估算容量后跟省略标记的容量、检查点失效、路由切换、容量变化、缺少容量和完全不变等场景。本修改不推断提供方容量，不改变压缩策略，也不会把估算值伪装成精确事实。

## 考虑过的替代方案

**只比较容量数值。** 这会保持旧的追加频率，却会在部署把回退值替换为精确声明时，让 UI 与下游消费方保留过时的来源标记。

**只在会话追加事件时校验标记。** 这会把适配器约定错误延迟到循环执行，并以 session 失败报告，而不是以无效模型元数据报告。

**从持久事件中删除估算标记。** 这会规避转换问题，却让用户界面和策略无法区分声明容量与回退容量。

## 影响

容量来源在 LLM 适配器边界得到校验，并在 request/context 去重和投影重放过程中无损保留。只影响来源标记的配置变化会增加一条日志记录；投影语义变化会使旧的上下文压力缓存状态失效，从而通过重放重建最新的完整容量记录。
