# Agent Note：在不可用根标记处界定指令发现范围

Status: implemented

中文 | [English](2026-08-18-context-root-marker-failure-boundary.md)

## 问题

Workspace 指令发现只区分根标记存在与其他所有结果。因此，文件系统 provider 的解析或元数据故障会被视为已确认缺失，发现过程随后继续进入父目录。自身标记暂时不可观测的 session 可能接收到来自另一个祖先项目的 `AGENTS.md` 内容。

## 决策

根标记探测具有三种结果：存在、缺失和不可用。任一已配置标记存在时，其目录成为项目根。已确认缺失允许继续向上搜索。当没有已配置标记存在且至少一个探测不可用时，当前目录成为保守根；发现过程保留该目录与 session cwd 之间的指令，但不会越过其父目录。Provider 与主机文件系统探测采用相同分类，路径缺失错误仍属于已确认缺失。

每次 context 合成都会重新计算项目根。暂时故障恢复后，常规基线身份比较可以用完整可观测的指令链替换保守指令链。

## 验证与边界

回归用例把 session 放在一个带标记的外层项目之下，使 session cwd 的标记探测失败，并为两个目录配置不同的指令文件。合成基线保留 cwd 指令并排除外层项目指令。现有覆盖继续区分已确认缺失标记、普通带标记祖先、多候选项、取消、恢复、不可用指令文件候选与本根发现规则。

该决策只界定根发现范围。所选指令链内的指令候选项仍遵循既有三态可用性和同级候选行为。

## 考虑过的替代方案

**继续把探测故障视为缺失。** 这样能在 provider 暂时故障期间保留更宽的发现范围，但会允许不可观测的目录边界把另一个项目的指令导入模型上下文。

**中止完整指令注入。** 这样能对祖先内容失效关闭，但也会丢弃可直接观测的 cwd 指令。在该目录界定根可以保留指令链中安全的部分。

**任何故障都回退到 session cwd。** 当故障发生在 cwd 上方数个目录时，这会不必要地丢弃故障目录下方的可观测指令。把故障目录本身作为根，是阻止跨越未知边界的最窄范围。

## 影响

Provider 和主机文件系统故障不再使 workspace context 跨越不可观测的根边界。暂时故障可能暂时省略有效的更宽范围指令，但保守根及其下方可直接观测的指令仍然可用，后续合成会在观测恢复后修复基线。
