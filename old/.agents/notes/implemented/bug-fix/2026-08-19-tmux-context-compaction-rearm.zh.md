# Agent Note: Tmux 上下文在压缩后重新启用

Status: implemented

[English](2026-08-19-tmux-context-compaction-rearm.md) | 中文

## Problem

Tmux 上下文曾同时使用最近的原始持久读数进行间隔调度和未变化状态抑制。压缩可以从模型表面遮蔽该读数，而原始事件仍会抑制之后相同的状态，导致实时会话和恢复会话无限期缺少任何可见的 tmux 快照。

## Decision

最近的持久 tmux 读数分别携带时间与可见性事实。原始事件时间继续控制 `refreshIntervalMs`，使同一调度跨压缩和进程恢复保持不变。只有该事件仍位于当前会话表面时，未变化状态抑制才生效。压缩将其遮蔽后，下一个满足间隔条件的首步骤会记录当前状态，即使 pane 没有变化。

## Verification

聚焦回归使用表面替换遮蔽初始读数，并分别继续实时 Session 和从相同事件恢复的 Session。在恰好达到间隔阈值时，两条路径都会记录第二条持久读数，而 `deriveMessages()` 只暴露一个当前 tmux 快照。

## Alternatives considered

**忽略表面可见性。** 已拒绝，因为压缩后的持久历史与模型可见上下文回答不同问题；一个时间戳无法证明模型仍能看到该状态。

**丢弃被遮蔽事件的时间。** 已拒绝，因为压缩会重置刷新间隔并允许立即查询，使调度取决于摘要时机，而非最近一次实际读数。

**保存进程内可见性状态。** 已拒绝，因为恢复和进程重启会丢失它，使同一持久会话重新表现出不同的行为。

## Consequences

被压缩的会话会重新获得一个当前 tmux 快照，同时不会在配置间隔内产生查询突发。原始历史可在压缩边界两侧包含多条相同读数，而当前模型表面只包含最新的可见读数。
