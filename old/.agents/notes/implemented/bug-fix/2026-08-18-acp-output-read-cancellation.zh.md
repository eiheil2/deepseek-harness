# Agent Note: 在自有清理边界取消 ACP 输出读取

Status: implemented

[English](2026-08-18-acp-output-read-cancellation.md) | 中文

## Problem

ACP 桥接层在提示词取消、客户端断开和插件释放期间等待有序的 assistant 图片转换，但调用 `AttachmentStore.readImage()` 时没有传入该服务接受的取消信号。因此，缓慢或卡住的附件后端可能会在所有者取消后阻止提示词乃至整个连接达到完全停稳状态。

## Decision

每个 ACP 会话为实时提示词之外的已提交输出拥有一个输出取消生命周期，每个已准入提示词拥有另一个独立的输出取消生命周期。Assistant 图片转换接收对应信号并将其传给附件存储。提示词取消会中止其准入和输出生命周期；连接清理会在等待有序交付前中止每个会话和提示词的输出生命周期。

取消仍与附件损坏分离。转换会保留已中止信号的原因，有序交付链把所有者请求的中止视为预期结算，而不记录输出失败或警告。非取消读取失败仍会让所属提示词失败并保留日志。

## Verification and boundary

ACP 连接测试在已提交图片之后挂起 assistant 附件读取，释放桥接层，并证明存储收到了已中止的信号、提示词以 cancelled 结算且 Agent 已被移除。现有输出顺序、附件缺失和显式 drain 测试维持原有行为。

本次变更会取消附件读取，因为其服务约定接受 `AbortSignal`。它不声称 ACP 传输写入可取消；这些 Promise 由 ACP SDK 所有，清理仍须等待其结算。

## Alternatives considered

**无限等待每次输出读取。** 这会保留顺序，却会在自有后端操作已暴露取消能力时违反清理义务。

**为输出复用准入控制器。** 准入和交付具有不同的结算点。独立控制器明确其所有权，也避免在用户消息入队后改变准入语义。

**在提示词取消时中止会话级控制器。** 这也会禁用同一会话中后续提示词的输出。提示词生命周期只取消其关联输出，会话生命周期仍可供无关联的已提交消息使用。

## Consequences

提示词取消和连接清理可以释放可取消的附件读取，而不必等待后端完成。有序交付和非取消失败报告维持不变。每个活动 ACP 会话和提示词各拥有一个额外的 `AbortController`。
